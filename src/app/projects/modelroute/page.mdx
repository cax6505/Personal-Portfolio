# Case Study: ModelRoute — Enterprise LLM Routing Engine

## Intelligent Multi-Provider LLM Orchestration & Fallback Engine

**ModelRoute** is an enterprise-grade LLM routing system that dynamically classifies incoming user prompts and dispatches them to optimal model providers (Groq, Gemini, local models) based on task intent, cost, latency, and capability tradeoffs.

**[GitHub Repository →](https://github.com/cax6505/ModelRoute)**

---

### Tech Stack
*   **Core & Framework**: Next.js 15 (App Router), TypeScript, Tailwind CSS, shadcn/ui
*   **Database & Cache**: Upstash Redis (Sliding-window Rate Limiter), Supabase (PostgreSQL Audit Logs)
*   **Testing & AI APIs**: Vitest, Groq API (Llama 3.3 70B/8B), Gemini API (Flash 2.0)

---

### The Problem
When building production AI applications, relying on a single LLM provider creates significant challenges:
1.  **Cost Inefficiency**: Routing simple Q&A queries to expensive frontier models wastes budget.
2.  **Vendor Lock-In & Outages**: Single provider downtime results in broken user workflows and service outages.
3.  **Rate Limits & Throttling**: Burst traffic causes API rate limit errors (HTTP 429) without intelligent fallbacks.
4.  **Lack of Observability**: Auditing prompt volume, provider latency, cost metrics, and fallback sequences is difficult across disparate provider APIs.

---

### Key Engineering Solutions & Architecture

#### 1. Multi-Mode Task Classification Engine
ModelRoute classifies user prompts across 8 intent categories (`code_generation`, `summarization`, `extraction`, `creative_writing`, `reasoning`, `simple_qa`, `translation`, `general`) using a hybrid strategy:
*   **Deterministic Rules Classifier**: High-speed regex and keyword matching for instant categorization with zero API latency.
*   **LLM Classifier**: Structured prompt classifier using lightweight models for complex or ambiguous intent identification.
*   **Hybrid Fallback**: Evaluates rules first; seamlessly falls back to LLM classification when rule confidence drops below target thresholds.

#### 2. Config-Driven Routing & Candidate Ranking
Maps classified intent and requested priority policy (`quality`, `fast`, `cheap`) to ranked candidate model chains. Generates transparent, audit-ready decision resolution strings for complete execution observability.

#### 3. Circuit Breaker Resilience (`CLOSED` / `OPEN` / `HALF_OPEN`)
To handle upstream provider degradation or outages:
*   **CLOSED**: Normal operation state.
*   **OPEN**: Automatically trips after N consecutive failures within a window, bypassing degraded providers immediately.
*   **HALF_OPEN**: Cooldown period triggers probe requests to verify provider recovery before restoring traffic.

#### 4. Enterprise Security & Rate Limiting
*   **SHA-256 API Key Storage**: Key credentials (`mr_live_...`) are hashed prior to storage in Supabase.
*   **Two-Tier Sliding-Window Rate Limiting**: Upstash Redis enforces burst limits (15 RPM) and total budget limits (100 RPH).
*   **Privacy-Preserving Auditing**: Prompt payloads are hashed with SHA-256 by default to protect privacy.

### Key Outcomes & Metrics
*   **Multi-Provider Coverage**: Supported seamlessly across Groq, Gemini, and local models.
*   **Fault Tolerance**: 100% request completion during simulated single-provider outages via automatic circuit breaker switching.
*   **Test Coverage**: Extensive Vitest suite covering classifier rules, rate limits, circuit breaker state transitions, and API routes.
